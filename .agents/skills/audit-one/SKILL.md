---
name: audit-one
description: Claim and ship one independent audit-plan issue with a single Codex worker alongside Claude. Accepts an item ID or the next eligible issue.
---

Use `$audit-one 26` for an exact plan ID, including IDs like `5a`, or `$audit-one next` for the first eligible issue in plan order. A bare invocation means next. Accept a pasted issue when it uniquely identifies a plan row. If an explicit target is blocked or ambiguous, report why and stop.

1. Locate the main checkout with `git rev-parse --path-format=absolute --git-common-dir` (its parent directory). Read the newest main-checkout `docs/audits/*-fix-plan.md`, or the user's specified plan. Use its decisions, dependency ordering and review rules. Follow the **Claims** and **Plan waves** rules in `.claude/skills/audit-fix/SKILL.md` for both Claude and Codex work.
2. Apply the Codex usage gate in AGENTS.md. Fetch origin. Inspect claims, local and remote branches, open PRs and `git worktree list --porcelain`. For active items include likely files from the plan as well as actual changed paths. Skip completed, taken, undecided, dependent and overlapping items. Treat live branches, worktrees and PRs as busy even if a claim expired. If a required lookup fails, report the uncertainty before claiming.
3. Use the shared `docs/audits/.plan.lock` under the main checkout and the same `in progress (<tag>, <ISO time>)` format as Claude. While holding it, reread all claims and recheck eligibility against newly busy items. Save the previous status and claim exactly one row. Release the lock before creating the worktree or launching. If setup or launch fails, restore the previous status under lock only if the claim still belongs to you.
4. Create a separate worktree on the plan's branch from fresh `origin/main`. A branch collision is a blocker. Spawn exactly one audit-fixer and give it the absolute worktree, branch, plan path, exact item, decision, audit IDs, relevant paths and required reviews. On clients with only a generic spawn tool, give that single worker the audit-fixer role file and same assignment. Keep plan writes and cleanup with the coordinator. Ask the worker to return the pushed PR before merge so the coordinator can enforce the plan's review requirements.
5. Track that PR through checks and required reviews. The coordinator can apply the relevant review checklists directly. If independent sign-off is required, obtain it through the existing PR review process before merging. For an item-owned failure, resume the same worker on the same branch. Reuse failure evidence for the same head SHA and job ID. Fetch only the missing diagnostics for each blocker. Follow the audit-fixer's update-from-main, lint, green-CI and merge rules. Keep a blocked PR open.
6. Under the shared lock, replace only your own claim with the verified result, PR and date. Return to the main checkout and remove only your own clean worktree. Preserve an unfinished worker's branch and work. Report the issue, PR, checks and outcome, then stop after this one item.
