# Правила: что мы делаем в каких случаях

Сводка решений команды и поведения системы в одном месте. Каждая строка — ситуация, что происходит и почему. Подробности и команды — по ссылкам. Пункты с пометкой **(в работе)** ещё не выпущены.

## Остановка контейнеров

| Ситуация | Что делаем | Почему |
| --- | --- | --- |
| Пользователь нажал **■ Stop** | Сначала сохраняются открытые файлы, затем контейнер останавливается (`docker stop` ждёт до 90 секунд), окно закрывается. Тома (рабочая копия, настройки Positron, R-пакеты) остаются. | Явная остановка — единственный обычный способ освободить память на сервере. |
| Пользователь просто закрыл окно | Контейнер продолжает работать и занимать память и квоту. | Чтобы долгий расчёт не прерывался из-за закрытого окна. |
| Остановка, в контейнере идут расчёты | Stop показывает, что ещё считает (консоли R и Python, другие процессы с нагрузкой на CPU), и просит подтвердить: **Stop Anyway**. | То, что сессии держат в памяти и не записали в файлы, при остановке теряется. |
| Простой: нет окна и почти нет нагрузки | Контейнер останавливается, когда `idleMinutes` минут подряд нет SSH-сессии (окна Positron), CPU ниже 5 % ядра и нет задач `fnkc-projects run`. На сервере значение задаёт администратор (в примере конфигурации — 120; без значения — `0`, никогда). Для Docker на своём компьютере — настройка `idleMinutes`, по умолчанию `0`. | Освободить память забытых проектов, не прервав расчёт. |
| Нет окна, но контейнер считает | Через сутки без окна Positron пользователя один раз в день спрашивает: **Keep 3 More Days** или **Stop Now**. Через 3 дня после закрытия последнего окна контейнер останавливается. **Keep** даёт ещё 3 дня с момента нажатия; подключившееся окно сбрасывает оба счётчика. | Бесконечные «зависшие» расчёты не должны навсегда занимать сервер, но настоящий долгий расчёт можно продлить. |
| Долгий расчёт, который должен пережить закрытие окна | Запускать через `fnkc-projects run <команда>`: остановка при простое его не прервёт. Явная остановка, перезапуск сервера и нехватка памяти — прервут; сохраняйте промежуточные результаты. | Ожидание ввода-вывода не должно выглядеть как простой. |
| Автоостановка и несохранённые правки | В контейнере Positron сохраняет файлы сам через 5 секунд после изменения (если пользователь не задал своё значение `files.autoSave`). | Остановка при простое не теряет правки в редакторе. |
| Нельзя прочитать счётчик CPU контейнера | Автоостановка выключается для этого контейнера. | Без счётчика расчёт не отличить от простоя: лучше не останавливать. |
| Отключение пользователя (`admin remove-user`) | Сначала проверяется, что вся работа пользователя в Gitea (иначе отказ; `--lose-work` отзывает сразу, без проверки); затем удаляется ключ, затем останавливается каждый работающий проект пользователя. Открытые соединения закрываются в течение 5 секунд. | Отозванный пользователь не может ни работать, ни запустить новый контейнер. |

Остановка никогда не меняет `renv.lock`: намеренные изменения пакетов фиксируются командой `fnkc-projects snapshot` заранее.

## Запуск и ёмкость сервера

| Ситуация | Что делаем | Почему |
| --- | --- | --- |
| Пользователь запускает ещё один проект | Допускается не больше `maxProjectsPerUser` (по умолчанию 2) работающих проектов и не больше `maxMemoryPerUser` (16 ГБ) суммарного лимита памяти. При превышении — отказ со списком своих работающих проектов и кнопкой **Stop a Project**. | Сервер общий; ограничение памяти каждого контейнера — потолок, а не резерв. |
| На сервере не хватает памяти | Допуск не раздаёт `reserveMemory` (2 ГБ) и считает контейнеры без лимита памяти занимающими ресурсы. Отказ — с кнопкой **Copy for the Administrator**. | Хост не должен уходить в нехватку памяти. |
| Обслуживание сервера | `maxProjectsPerUser: 0`: новые запуски запрещены, работающие проекты продолжают работать. | Можно подготовить остановку, не прерывая чужие расчёты. |

## Изменения и обновления

| Ситуация | Что делаем | Почему |
| --- | --- | --- |
| Изменилась настройка, закрепление образа, ключ или версия fnkc-ctl, а контейнер работает | Работающий контейнер **никогда не заменяется**. Open подключается к нему как есть и сообщает, что обновление ждёт явной остановки. Образ нового закрепления, которого нет на хосте, для этого не нужен: клиент присылает его при первом открытии после остановки. | Не прерывать идущую работу. |
| То же, контейнер остановлен | Следующее открытие пересоздаёт контейнер; тома сохраняются. | Новые настройки (`cranMirror`, `extraHosts`, `idleMinutes`, лимиты) применяются при создании контейнера. |
| Новый выпуск fnkc-ctl | Обновляем **сначала сервер**, потом клиенты. Сервер принимает клиентов предыдущего выпуска. Расширение раз в день проверяет выпуск и предлагает его, только если все отвечающие серверы его поддерживают. | Клиент не должен опережать сервер. |
| Версия Positron | Команда использует одну закреплённую версию (`env/positron.args`), автообновления Positron выключены (Check Setup предлагает `update.mode: none`). Нужен сервер для другой версии — **Build Environment**. Переходим на новую версию вместе. | Сервер Positron в образе подходит только к своей сборке. |

## Образы окружения

| Ситуация | Что делаем | Почему |
| --- | --- | --- |
| Какой образ запускать | Только из точных разрешённых репозиториев (`allowedImages`) и только по дайджесту. На сервере образ должен иметь GitHub Artifact Attestation от `positron.yml` из `main`; проверка офлайн. | Дайджест доказывает содержимое, attestation — происхождение. |
| На хосте нет нужного образа | По умолчанию (`pullImages: false`) клиент скачивает его на своём компьютере и передаёт через шлюз, хост проверяет дайджесты. С `pullImages: true` хост сначала пробует `docker pull`. | Работа не должна зависеть от доступа сервера к реестру. |
| Загруженный образ без записи о загрузке (`loaded/<digest>`: загружен старой версией fnkc-ctl или вручную) | Контейнер проекта из него не создаётся, не заменяется и не запускается: Open просит клиент прислать образ заново. Работающий контейнер, созданный из этого же образа, Open подключает как есть, без повторной загрузки (checkout читается этим же образом, только для чтения). Администратор может сделать запись командой `fnkc-ctl admin record-image`, только если контейнер проекта, созданный fnkc-ctl с этим закреплённым образом, использует ровно тот образ, на который указывает тег. Тег, перенесённый на другой образ, и повреждённая запись не принимаются никогда. | Тег можно перенести на любой образ; запись — нет. Работающий контейнер не прерываем. |
| Нужен R-пакет | Все пакеты команды — в образе. Пакет для одного проекта — `renv::install()` из зеркала CRAN (`cranMirror`) и затем `fnkc-projects snapshot`. Расширить командный образ — derived-образ, который только добавляет пакеты. | Окружение воспроизводимо и не зависит от сети при запуске. |
| Сборка окружений | **Build Environment** запускают только администраторы. Неизменённые серии не публикуются заново. | Новый дайджест у каждой пересборки; меньше лишних образов. |
| Очистка реестра | `fnkc-ctl images --cleanup` только показывает. С `--delete` удаляются: не самые новые окружения серии, не закреплённые шаблоном и неиспользуемые, старше 30 дней; слои старых версий Positron старше 60 дней без контейнеров; неиспользуемые старые монолитные образы; слои без окружения. Если хост, шаблон или реестр не прочитан — отказ. | Нельзя удалить то, чем кто-то пользуется. |
| Образ на сервере больше не нужен | Удаляет администратор (`sudo docker image rm <id>`); Docker откажет, если образ использует контейнер. Не выполнять `docker system prune --volumes`. | Тома остановленных проектов — работа пользователей. |

## Данные и шифрование

| Ситуация | Что делаем | Почему |
| --- | --- | --- |
| Проект с зашифрованными данными | Расшифровка — только в Docker своего компьютера и на серверах из `decryptionHosts`. Личный ключ GPG остаётся на компьютере, ключ проекта не пишется в файл. Расшифровка сохраняется в томе. | Ключи не покидают компьютер пользователя. |
| ИИ-агенты и проверки PR | Только одноразовый клон и синтетические данные, без ключа расшифровки и без тома аналитика. Расшифрованную рабочую копию никогда не используем как рабочее место агента. | Коду не нужно видеть данные, чтобы их раскрыть. |
| Отчёт на реальных данных | Только через `render-reviewed.py` по согласованию конкретного коммита; результаты автоматически не публикуются и проверяются перед раскрытием. | [Правила работы с чувствительными данными](data-execution.md). |

## Удаление проекта

| Ситуация | Что делаем | Почему |
| --- | --- | --- |
| Удаление с панели | Проект должен быть остановлен. Сначала проверка: если вся работа в Gitea — так и пишет; если нет — отчёт о каждом файле и коммите, которые потеряются, и второе подтверждение. Перед удалением содержимое проверяется ещё раз и при изменениях удаление отменяется. | Удаление необратимо; репозиторий в Gitea не меняется. |

## Сбои и восстановление

| Ситуация | Что делаем | Почему |
| --- | --- | --- |
| Процесс умер во время замены контейнера | Старый контейнер остаётся под именем `fnkc.recovery.<user>.<project>`; следующее открытие само его восстанавливает или завершает замену. Тома проекта не удаляются. | Ни один сбой не должен терять работу. |
| Новый контейнер после замены запущен, но не проходит проверку готовности | Open показывает ошибку с концом журнала и предлагает **Discard and Retry**: неготовый контейнер удаляется (тома остаются) и создаётся заново. Готовый контейнер так никогда не удаляется. Вторая неудача — сообщение «окружение не запускается на этом сервере»: к администратору или вернуть прежний образ. `fnkc.recovery.*` остаётся для администратора до следующего успешного запуска; отката к нему у аналитика нет. | Неготовый контейнер ещё никому не служил; старый оставляем для разбора. |
| Прерванное первое клонирование | Следующее открытие продолжает его. Непустые рабочие копии автоматически не удаляются. | — |
| Файлы блокировок `*.kernel` | Никогда не удаляем. Блокировка освобождается сама при завершении процесса. | Удаление создаёт вторую, независимую блокировку. |
| Откат образа | Вернуть предыдущий дайджест в `container.json`, остановить и открыть проект. Файлы проекта и данные откатываются отдельно. | — |

## Резервное копирование

Копируем только остановленные проекты: скрипт отказывается работать с томом работающего контейнера и берёт ту же блокировку проекта. Копируются тома `<base>-project`, `<base>-data` и `<base>-library`. Репозиторий restic — зашифрованный и внешний. Снимок из неудавшегося задания не восстанавливаем. Начальная цель — ежедневное копирование и ежемесячные учения по восстановлению ([руководство оператора](operations.md#резервное-копирование-и-учения-по-восстановлению)).
