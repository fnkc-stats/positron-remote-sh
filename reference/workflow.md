# Инструкция

## Первая настройка

1. Получите у администратора: адрес сервера и отпечаток (fingerprint) его SSH-ключа хоста, адрес Gitea, адрес репозитория. Отправьте администратору свой **публичный** SSH-ключ (`~/.ssh/id_ed25519.pub`), чтобы он подключил его на сервере, и добавьте этот же ключ в свою учётную запись Gitea. Закрытый ключ никогда никому не отправляйте.
2. Установите Positron той версии, которую назовёт администратор (для неё собраны образы), и выключите его автоматические обновления: это предложит Check Setup. Затем установите расширение из последнего выпуска:

   ```sh
   curl -fL https://github.com/fnkc-stats/positron-remote/releases/latest/download/fnkc-projects.vsix -o /tmp/fnkc-projects.vsix
   "/Applications/Positron.app/Contents/Resources/app/bin/code" --install-extension /tmp/fnkc-projects.vsix --force
   ```
   (на Windows: скачайте файл по ссылке и выберите его в Positron: **Extensions → … → Install from VSIX**). Дальше расширение обновляется само: раз в день оно проверяет новый выпуск и предлагает **Update** (вручную: кнопка **Check for Updates** в заголовке панели Projects или **FNKC Projects: Check for Updates**).
3. Получите у администратора файл `config.json` и выполните **FNKC Projects: Import Configuration…** (кнопка есть и на панели Projects): расширение проверит файл и положит его в `~/.config/fnkc-ctl/config.json`, где его читает и командная строка. Пример для администраторов: [ctl/examples/config.json](../ctl/examples/config.json).
4. Сверьте ключи хостов сервера и Gitea с отпечатками, которые вам дали администраторы, и только после этого добавляйте их в `~/.ssh/known_hosts`. Загрузите свой ключ командой `ssh-add`.
5. Выполните **FNKC Projects: Check Setup** из палитры команд и исправьте всё, о чём она сообщит.

## Открытие проекта и работа

Выполните **FNKC Projects: Open Project…**, введите имя репозитория (например, `thesis`) или его полный SSH-адрес и выберите разрешённый сервер. Работайте в открывшемся окне, коммитьте и пушьте как обычно.

Проект в списке называется так же, как репозиторий в Gitea; так же называется и папка в контейнере. При первом открытии репозиторий клонируется внутри контейнера (`git clone` с вашим ssh-agent) на тот коммит, который был найден при открытии; на ваш компьютер скачивается только `container.json`. При повторном открытии ваша ветка, изменения и локальные коммиты сохраняются. Если Gitea недоступна, проект, который уже есть на выбранном сервере, всё равно открывается: окружение и коммит берутся из его рабочей копии на сервере, даже на компьютере, с которого проект раньше не открывали. Проект, которого на сервере ещё нет, без Gitea не откроется: его нужно склонировать. **Sync** только скачивает изменения с сервера Git (fetch); слияния и переключения веток делайте сами, осознанно. После изменения `container.json` (окружения проекта) откройте проект заново. Если обновление ждёт, пока контейнер работает, открытие всё равно подключается к работающему контейнеру и предупреждает об этом: дождитесь окончания расчётов, сохраните файлы, остановите проект и откройте его снова. Обновление расширения появляется только после того, как администратор обновит сервер.

Новый репозиторий создавайте в Gitea из шаблона нужной версии R (**New Repository → Template**): в нём уже есть `container.json` и `renv.lock`.

## Первое открытие на сервере занимает время

Долгое открытие можно прервать кнопкой **Cancel** в уведомлении: то, что сервер уже сделал, сохраняется или откатывается, следующее открытие продолжит. Если открытие прервано во время скачивания или отправки образа окружения, появится сообщение с кнопкой **Retry Open**: она открывает тот же репозиторий на том же хосте, ничего не спрашивая заново, и продолжает с уже скачанного. Скачанные для отправки образы хранятся в кеше компьютера (`~/.cache/fnkc-ctl/images`), не больше `imageCacheLimit` (по умолчанию 20 ГБ); очистить его: **FNKC Projects: Clear Image Download Cache**.

Когда образ окружения открывается на сервере впервые, ваш компьютер скачивает его (для `r-env` около 1,5 ГБ, вместе с сервером Positron) и отправляет на сервер. Сервер проверяет их и хранит для всех. Это занимает несколько минут, следующие открытия — секунды. Не закрывайте окно, пока открытие не завершится; если оно прервалось, следующее открытие использует то, что ваш компьютер уже скачал. Пока идёт одно открытие, можно открывать другие проекты; два открытия, которым нужен один образ, скачивают его один раз (второе ждёт), а если на сервер в это время загружает образ коллега, открытие ждёт своей очереди и пишет об этом.

## R-пакеты

Основные R-пакеты берутся из образа окружения. Проект из шаблона Gitea содержит `renv.lock` своей серии R: первая консоль R восстанавливает его сама, ничего не скачивая. Пакет, которого в образе нет, установите через `renv::install("pkg")`: он скачивается из зеркала CRAN команды (https://mirror.truenetwork.ru/CRAN/) и собирается из исходников (`install.packages()` не используйте), затем, до следующего запуска R, выполните в терминале `fnkc-projects snapshot`: команда записывает в `renv.lock` пакеты, установленные в проект, вместе с зависимостями. Остановка проекта `renv.lock` не меняет: без `snapshot` установленный пакет не попадёт в lock-файл. Проверьте и закоммитьте `renv.lock`: у коллег он восстановится сам. Не выполняйте `renv::init()`. Если у хоста нет сети или пакет нужен многим проектам, попросите добавить его в командный образ `r-env` ([r-packages.md](r-packages.md#renv)).

Если в вашем `~/.ssh/config` есть общие правила `Host *` с `ProxyJump` или `ProxyCommand` (например, корпоративный бастион), на подключения к проектам они не действуют: записи FNKC Projects задают свой маршрут явно.

## Где лежат ваши файлы

Ваша рабочая копия хранится в именованном томе Docker на выбранном сервере. Это не обычная папка на вашем ноутбуке. Держите код, результаты и заметки внутри рабочей копии: остальные файлы в домашней папке могут пропасть при замене контейнера. Регулярно коммитьте и пушьте. Перед переходом на другой сервер запушьте свою работу: если сервер недоступен, проверить, остались ли незапушенные изменения, нельзя.

## Зашифрованные данные

Если данные проекта зашифрованы и рабочая копия ещё не расшифрована, **Open Project…** спросит, расшифровать ли их. Ответьте **Decrypt**: ваш личный ключ GPG на этом компьютере открывает ключ проекта (`.git-crypt/keys/default/0/<отпечаток>.gpg` в репозитории; GnuPG может спросить пароль ключа), и ключ проекта передаётся в `git-crypt unlock` в контейнере по SSH. Ваш личный ключ остаётся на компьютере, ключ проекта не записывается в файл ни там, ни в контейнере. Нужен GnuPG на компьютере с паролем ключа в отдельном окне (macOS: `brew install gnupg pinentry-mac` или GPG Suite, Windows: Gpg4win): **Check Setup** проверяет GnuPG, личный ключ и окно для пароля и подсказывает команду, если чего-то не хватает. Если проект не зашифрован для вашего ключа, Open сообщит отпечаток ключа: коллега с доступом добавляет вас командой `git-crypt add-gpg-user <отпечаток>`. Для проекта с общим файлом ключа git-crypt укажите этот файл в настройке `gitCryptKey`.

Расшифровать данные можно в Docker на этом компьютере и на серверах из настройки `decryptionHosts` (её значение приходит в `config.json` от администратора). Расшифровка нужна один раз: она сохраняется в томе проекта, и обычное открытие, остановка или замена контейнера не шифрует данные снова. Из командной строки: `fnkc-ctl open <проект> --unlock`. В терминале контейнера по-прежнему работает `fnkc-projects unlock <файл ключа>`. Закончив, выполните `fnkc-projects lock` в чистой рабочей копии (без незакоммиченных изменений), а расшифрованные отчёты, кеши, временные файлы и выгруженные данные обработайте отдельно. Никогда не используйте эту рабочую копию как рабочее место для ИИ-агента.

## Долгие расчёты

Запускайте долгие расчёты так:

```bash
fnkc-projects run Rscript analysis.R
fnkc-projects run quarto render report.qmd
```

На сервере контейнер без окна и без нагрузки останавливается через 2 часа. Эта обёртка не даст принять ожидание ввода-вывода за законченную работу. Контейнер, который считает без окна, останавливается через 3 дня после закрытия последнего окна; через сутки Positron предложит **Keep 3 More Days**. При остановке теряется то, что сессии R и Python держат в памяти: сохраняйте результаты в файлы. Расчёт, запущенный через неё, всё равно прервётся при явной остановке проекта, перезапуске сервера или нехватке памяти. Для долгих расчётов сохраняйте промежуточные результаты.

## Остановка

**FNKC Projects: Stop This Project and Close the Window** сначала сохраняет файлы, а затем останавливает проект на сервере этого окна (окно закрывается сразу, остановка идёт в фоне; если она не удалась, следующее окно Positron скажет об этом и предложит **Stop Again**). Остановка не меняет `renv.lock`. После намеренной установки пакетов выполните `fnkc-projects snapshot` в терминале контейнера, проверьте и закоммитьте изменения до остановки. Не останавливайте проект, пока идут расчёты. Просто закрыть окно — не то же самое, что остановить: расчёты могут продолжаться. Ограничение памяти может завершить R; часто сохраняйте промежуточные результаты и, прежде чем просить больше памяти, обсудите это с администратором.
